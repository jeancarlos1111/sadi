
# SADI Buenas Prácticas y Reglas de Desarrollo
Debes cumplir ESTRICTAMENTE las siguientes buenas prácticas en todo el código PHP y vistas PHTML:
- **Tipado estricto:** Incluir `declare(strict_types=1);` al inicio de TODOS los archivos PHP.
- **DTOs Inmutables:** Usar clases `readonly` para los Modelos/DTOs. No incluir lógica de negocio en ellos (separación de responsabilidades).
- **Serialización en DTOs:** Implementar siempre métodos `fromArray()` y `toArray()` en los modelos/DTOs.
- **Seguridad en Vistas:** Usar siempre `htmlspecialchars()` al imprimir variables en las vistas (`.phtml`) para prevenir XSS.
- **Autocompletado IDE:** Incluir bloques de documentación `@var` al inicio de las vistas `.phtml` para tipar las variables inyectadas.
- **Uso de Componentes Reutilizables (Vue-style en PHP):** Para evitar la duplicación de código en la UI (DRY), utilizar SIEMPRE el helper `render_component(nombre, props)`. Por ejemplo, para los botones de acción en las tablas (Ver, Editar, Eliminar) se debe utilizar: `<?= render_component('table_actions', ['editUrl' => '...', 'deleteUrl' => '...', 'deleteId' => $item->id]) ?>`. Nunca crear el HTML de estos botones manualmente.
- **Auditoría Obligatoria:** El sistema es completamente auditable. Cada vez que se cree, modifique o elimine un registro principal en cualquier módulo, debes registrarlo utilizando el método `$this->audit('nombre_tabla', 'ACCION', $idRegistro, $datosAntes, $datosDespues)` heredado del `BaseController`. Al editar o eliminar, asegúrate de recuperar el estado previo desde el repositorio.
- **Búsqueda Dinámica y Paginación (Server-Driven UI / AJAX):** Cuando se requiera implementar búsquedas dinámicas o recarga de tablas en tiempo real mediante AJAX, **NO SE DEBE UTILIZAR JSON** para renderizar la tabla del lado del cliente. En su lugar, se debe utilizar el patrón Server-Driven UI (HTML-over-AJAX). El backend debe detectar la petición AJAX (e.g. `&ajax=1`), compilar la vista en PHP respetando el uso de `render_component()`, y devolver el fragmento HTML correspondiente para que JavaScript únicamente reemplace el contenedor (ej. `.ajax-table-container`) en el DOM. Esto garantiza que no se duplique lógica de UI en JS y se respeten las reglas de componentes.
- **TDD (Test-Driven Development):** Todo nuevo módulo o fase debe estar acompañado de sus respectivas pruebas automatizadas (Feature Tests, Unit Tests). Antes de finalizar la tarea, se debe ejecutar `php cli/sadi test` y garantizar que todos los tests pasen exitosamente sin errores, cubriendo casos felices y de fallo. No se debe dar por terminada la fase sin validar sus pruebas correspondientes.
- **Bloqueo Financiero Estricto:** Los documentos críticos (como Órdenes de Compra, Solicitudes de Pago, Nóminas) NO deben generar efectos financieros (ej. descontar disponibilidad presupuestaria, pre-compromiso o emitir pagos) a menos que su `estado_aprobacion` sea estrictamente `APROBADO`. Ningún documento en `ELABORACION` o `REVISION` tiene validez financiera.
